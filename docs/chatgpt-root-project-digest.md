`root` is overloaded in Linux: it can mean the filesystem root `/`, the root
user, or the root of a repository. In public docs, prefer `Root Project` or
another more specific name until the brand is clearer.

## Project Shape

The strongest thread is not "buy land, then build a restoration site". It is a
lighter movement model:

```text
train people -> connect them to landowners -> restore many places -> publish
the learning -> improve the next site
```

The land projects become downstream effects of a capability network. The useful
product may be a progression system that helps ordinary people become competent
ecological restorers.

## Core Ideas

### 1. Progression Ladder

The project can work like a practical guild or scouting-style skills ladder:

- begin with low-risk home or local observation tasks
- progress through water, soil, planting, monitoring, and maintenance skills
- use evidence, review, and permissions before physical intervention
- let experienced people mentor, lead, and eventually get paid

This fits the Living Water Handbook direction: evidence, logbook, review ladder,
and staged competence.

### 2. Three-Sided Network

The useful marketplace is not only "people visit a site". It is a network of:

- landowners with degraded or underused land
- learners/restorers who want meaningful practical experience
- mentors and specialists who can supervise safely

This avoids requiring the movement to own all the land before it can begin.

### 3. Open Source Restoration

The open-source idea is broader than code. It can apply to:

- restoration methods
- site playbooks
- accommodation designs
- governance and finance patterns
- mistakes and lessons learned
- monitoring and public evidence cards

The public promise is compounding learning: every project improves the next one.

### 4. Portugal Reconnaissance

The Portugal work should be treated as reconnaissance before commitment. The
highest-value trip shape is:

- visit existing eco-tourism, regeneration, vineyard, farm, and rural retreat
  projects
- collect planning and licensing lessons
- test translation, meeting capture, and video capture workflows
- map public planning constraints before spending professional money

Planning/GIS material may help filter land, but real site visits answer the
human questions: comfort, remoteness, family appeal, visitor experience, and
operator reality.

### 5. Pioneer Crew Before Visitor Village

Two phases should remain distinct:

- Pioneer Water Crew: temporary, practical, minimal infrastructure, restoration
  setup, tools, safety, water, toilets, showers, food, power, connectivity.
- Visitor Village: comfortable, family-friendly, repeatable, revenue-producing.

Do not design the polished visitor village before understanding the pioneer
setup path.

### 6. AI As Cheap First-Pass Leverage

AI is useful before expensive expert work:

- compare similar projects
- generate feasibility questions
- draft partner outreach
- map planning documents and risks
- create publicity, FAQ, manifesto, and pitch material
- translate and summarize meetings

AI should get the project onto the right road, then humans and experts validate
the decisions.

## Retrieval And Evidence Angle

This project should be organised for later retrieval from the beginning:

- every site visit, call, partner, planning document, and idea should become a
  source card
- raw capture stays private until reviewed
- public docs should cite source cards rather than copy private notes
- decision records should distinguish observation, interpretation, plan, and
  permission state
- retrieval tests should prove that questions like "what did we learn about
  planning risk?" return the right source cards, not a confident hallucination
